# 评测环节升级方案

> 更新时间：2026-07-29

---

## 一、现状分析

### "学 AI" 路径（7题）

- 纯规则打分：`LEVEL_MAP` / `DIRECTION_MAP` 硬编码映射，答案组合固定 → 报告固定
- 没有交叉分析（如"零基础+想转行"和"零基础+纯粹好奇"的建议差异不够细）
- 报告生成是字符串拼接，无 LLM 参与，缺少个性化解读

### "用 AI" 路径（3题）

- 太浅——只有场景、频率、工具三个维度
- prompt 模板是静态的，不会根据用户具体场景调整
- 报告几乎是固定模板填空

### 通用问题

| 问题 | 说明 |
|------|------|
| 缺少多维评分 | 只有一个 level，缺少"适合度"、"投入产出比"等维度 |
| 没有历史对比 | 用户重做评测看不到变化 |
| 报无可分享性 | 纯文本，没有可视化 |

---

## 二、升级方案

### P1 — LLM 驱动的智能报告（优先级最高）

**目标**：把 `generate_report` 从规则拼接改为 LLM 生成个性化报告。

**改动点**：
1. 收集所有评测答案，构造结构化 prompt 发给 LLM
2. LLM 根据答案组合生成个性化分析和建议
3. 保留规则版报告作为兜底（LLM 挂了或超时就退回旧版）

**技术方案**：
- 新增 `report_prompt.py`：定义报告生成的 system prompt + 答案模板
- 修改 `agent/evaluation/report.py` 的 `generate_report` 和 `render_use_ai_report`
- 调用现有 LLM 客户端（复用 `agent/core.py` 中的调用逻辑）
- 加超时和降级：LLM 5s 内没返回就用规则版

**预期效果**：
- 报告有"人味"，能根据答案组合灵活给出建议
- 同样的答案，每次生成的措辞不同，不机械

**工作量**：约 3-5 天

---

### P2 — 多维评分 + 雷达图

**目标**：从单一 level 升级为多维度评估，前端用雷达图可视化。

**新增评估维度**：

| 维度 | 评分依据 | 分值范围 |
|------|---------|---------|
| 学习适合度 | 目标 + 背景 + 编程基础 | 1-5 |
| 时间投入匹配度 | 可用时间 vs 推荐学习时长 | 1-5 |
| 预算匹配度 | 预算 vs 目标路径成本 | 1-5 |
| 方向明确度 | 方向选择 + 目标清晰度 | 1-5 |
| 综合推荐度 | 加权平均 | 1-5 |

**改动点**：
1. `config/evaluation.py`：新增维度权重配置
2. `agent/evaluation/report.py`：新增 `calculate_scores()` 函数
3. `agent/schemas.py`：`SessionState` 新增 `evaluation_scores: dict`
4. 前端：引入 ECharts，新增雷达图组件
5. 报告模板：加"你的优势/短板"分析段落

**预期效果**：
- 用户一眼看到自己的强项和短板
- 雷达图可截图分享

**工作量**：约 3-4 天

---

### P3 — 评测历史 + 对比

**目标**：支持多次评测，用户可以看到自己的变化。

**改动点**：
1. 数据库：新增 `evaluation_history` 表（session_id, timestamp, answers, scores, report）
2. API：新增 `GET /evaluation/history/{session_id}` 接口
3. 前端：新增"我的评测记录"页面，列表展示历次结果
4. 对比功能：选两次评测，展示分数变化（折线图或并排雷达图）
5. 导出：支持生成图片/PDF 用于分享

**工作量**：约 5-7 天

---

## 三、实施建议

| 阶段 | 内容 | 时间 | 依赖 |
|------|------|------|------|
| 第一阶段 | P1 LLM 智能报告 | 3-5 天 | 无 |
| 第二阶段 | P2 多维评分 + 雷达图 | 3-4 天 | P1 完成后 |
| 第三阶段 | P3 评测历史 + 对比 | 5-7 天 | P2 完成后 |

**建议先做 P1**，体验提升最大，改动最小。P2、P3 视需求再决定是否推进。

---

## 四、风险点

1. **LLM 成本**：每次评测多一次 API 调用，需评估 token 消耗
2. **响应时间**：LLM 生成报告可能比规则慢 2-3 秒，需加 loading 动画
3. **一致性**：LLM 可能给出与规则版矛盾的建议，需校准 prompt
4. **降级策略**：必须保留规则版兜底，避免 LLM 故障影响核心功能
